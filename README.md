# ScriptDeck 1.8.6

## 1.8.6 项目整理

项目目录、Swift 包和构建目标统一为 ScriptDeck，Bundle ID 为 `com.lucasyou.ScriptDeck`。项目根目录独立管理 Git，构建与打包不依赖父目录文件。配置从新的 ScriptDeck 目录开始，不迁移旧应用偏好、旧脚本库或旧定时计划。

macOS 13 及以上的原生脚本管理应用。本次发布包按本机 Apple Silicon 架构编译。

## 原生界面

界面采用 Finder 风格的系统分栏导航、可折叠侧栏和统一工具栏。macOS 26 及以上使用系统 Liquid Glass 操作栏与主要按钮；macOS 13–15 自动使用兼容材质与标准按钮。脚本参数和日志保持清晰的系统内容底色，随系统适配浅色和深色外观。

脚本配置采用分组表单，基本信息与执行配置分区，参数独立编辑，保存和取消始终位于底部。设置提供 Workspace 列表与终端字体预览，执行历史支持结果图标、筛选与日志分页。

## 1.8.3 面板对齐

Workspace 标题和选择器与侧栏内容左对齐。定时任务面板填满右侧可用区域，标题固定在顶部，说明固定在底部；没有任务时，空状态在中间内容区水平、垂直居中。

## 1.8.2 窗口布局修复

主内容使用受窗口可用尺寸约束的原生分栏，顶部避开标题栏和窗口按钮；脚本列表独立滚动，底部定时任务入口保持可见，切换页面不改变侧栏位置。侧栏显隐仍可通过工具栏按钮或快捷键控制。

## 1.8.1 固定侧栏导航

点击“全部定时任务”只切换右侧内容，侧栏的 Workspace、搜索、脚本列表和定时任务入口保持固定，不再插入返回按钮。脚本与定时入口只高亮一项；再次点击同一个脚本也可直接返回。页面切换保留参数、表单滚动位置、搜索与文件夹展开状态；查看全部计划时切换 Workspace，右侧继续显示全部计划。

## 1.8 系统定时任务

左侧分为 Workspace 脚本区和“定时任务”入口。在“全部定时任务”中新建，或在脚本参数填写完成后点击运行栏的“定时…”，保存当前脚本配置与参数快照。

- 支持一次性、每天、每周和每隔 N 分钟（最短 1 分钟）。列表显示下一次执行、最近结果及失败原因，支持编辑、暂停、重新启用和删除。编辑保存会重新启用并重新计算下次时间；已触发的一次性任务需编辑到未来时间才能再次启用。
- 使用当前用户的 macOS `launchd` LaunchAgent，无需管理员权限。关闭窗口或退出 App 后，后台仍能触发和执行；电脑必须开机且该用户已登录，不会主动唤醒电脑。休眠或退出登录期间错过的时间，恢复触发后最多补执行一次，不追赶全部次数。日历任务按创建时的时区计算，下次执行时间按当前系统时区展示；规则使用其他时区时会注明。
- 同一定时任务用跨进程文件锁防止重叠；上次未结束时，系统不会启动第二个实例。其他定时任务和手动任务可以并行。一次性任务启动前先消费执行时刻；即使失败也不会自动重试，可编辑后重新安排。
- 后台执行不提供交互式 PTY，标准输入为空；脚本应能无人值守运行。输出、错误和结果写入现有 `logs/脚本文件名/`，App 打开后同步到运行输出左侧任务列表，终端为只读日志视图，可停止或强制停止。历史窗口保留全部运行；任务列表只恢复各定时任务最近的一次，移出记录不会在本次 App 会话中重新出现。
- 暂停只取消后续计划，当前任务继续运行；停止请使用运行输出中的停止按钮。编辑和删除需要等待当前执行结束。删除计划、移除 Workspace 或移除脚本配置都不会删除日志；定时配置使用独立快照，移除 Workspace 登记后计划仍然有效，迁移脚本路径后需要重新配置计划。
- 任务配置与参数保存在 `~/Library/Application Support/ScriptDeck/Schedules/`（仅当前用户可读写），固定路径后台执行器位于其 `bin/ScriptDeck Helper`；移动 App 不影响既有计划。系统配置位于 `~/Library/LaunchAgents/com.lucasyou.ScriptDeck.schedule.<任务ID>.plist`。删除计划会卸载对应配置；已完成的一次性计划在 App 下次刷新时清理系统注册。
- 菜单栏显示运行任务数、启用中的计划数、最近异常和下次执行时间。退出时仅要求先结束手动执行会话，后台计划和正在执行的定时任务可以继续运行。

构建和打包不会自动安装任何定时任务。只有在 App 中保存并启用计划时才注册系统服务；App 后续启动会恢复已有计划的注册。后台执行器会额外做分钟级到期检查，系统负载、休眠及系统调度可能使实际触发晚于显示时刻，不提供秒级准时保证。

## 1.7.3 菜单栏与后台驻留

关闭主窗口后应用继续运行，已有脚本不受影响。菜单栏空闲时显示终端图标，执行时显示运行图标及任务数；展开可查看运行任务和最近结束结果，点击任务可选中并打开主窗口，也可进入设置或明确退出。点击 Dock 图标可重新显示主窗口。退出时仍保护手动运行的任务并等待日志保存完成，1.8 的后台定时执行可独立继续。

## 1.7 多执行会话

支持同时运行多个脚本，也可以使用不同参数多次运行同一脚本。每次执行独立持有进程、交互终端、运行状态和日志；未设置并发数量上限；1.8 另增加系统定时任务。

- 展开底部“运行输出”，左侧显示本次应用会话的任务列表，分为“运行中”和可折叠的“已完成”；右侧显示选中任务的终端。列表可拖动调整宽度，也可通过标题栏按钮隐藏。
- 任务条目上行显示 Workspace 首字符 Tag、脚本名和右对齐的运行时长（分:秒／时:分:秒）；下行显示状态图标及启动日期和时刻，用于区分同一脚本的多次执行。结束后时长固定为实际耗时，悬停可查看完整名称和状态。点击切换终端，隐藏的任务继续执行并保存输出；已有任务运行时，新启动任务不会自动切走当前终端。
- 中断、停止、强制停止、复制、保存和清空终端都只作用于当前选中的执行；⌘. 同样停止所选任务。选中已结束任务时，不会误停止其他运行任务。
- 输出面板收起时仍显示运行任务数量。运行任务可以跨 Workspace 并发；任一 Workspace 存在活动任务时，都不能移除或重新定位该库。
- 选中已完成任务后，点击列表底部垃圾桶按钮，或右键选择“删除此记录”，可单独移出该任务记录；运行中或正在保存日志的记录不能移除。仅移出本次会话列表，保留历史和日志；永久删除请使用“历史记录”中的删除功能。
- 左下角“移出已完成任务”按钮释放已结束且日志保存完成的终端缓冲区，不删除历史记录或日志文件。保留的终端较多时会占用更多内存，可按需移出。
- 执行历史同时识别所有运行中的记录，保护它们及尚在保存中的日志。退出应用前需要结束手动运行的任务，并等待其日志保存完成；定时任务不依赖 App 生命周期。

## 1.6 本地执行日志与历史记录

从此版本开始，每次真正启动的脚本都会自动创建独立执行记录，存放在脚本文件所在目录的 `logs/脚本文件名/` 下，文件名保留扩展名以区分同名脚本。例如：

```text
scripts/
├── upload-netfly-app.sh
└── logs/
    └── upload-netfly-app.sh/
        ├── 2026-11-06_20-30-00-123_<UUID>.log
        └── 2026-11-06_20-30-00-123_<UUID>.json
```

`.log` 持续追加可读输出；`.json` 记录脚本和 Workspace 的启动时信息、开始/结束时间、执行结果、退出码（可获取时）及日志文件名。目录使用脚本文件所在位置，不受工作目录 cwd 设置影响。日志不受终端滚动历史行数限制，清空终端不会删除日志。

- 点击运行输出右侧的“历史记录”，弹窗汇总所有脚本的执行记录，按时间倒序显示；可按 Workspace、脚本筛选和搜索。
- 选择记录可查看结果、时间、耗时和日志。长日志每页 256 KiB，默认显示最后一页，可向前翻阅全部内容，也可打开完整日志或在 Finder 中定位。
- 正在运行的记录支持刷新，选中当前任务时约每 2 秒更新预览；结束后自动更新结果。应用异常退出留下的运行中记录会显示“未正常结束”，已有输出保留。
- ANSI 颜色与控制序列会过滤，覆盖式进度刷新按先后顺序另起一行保存；历史日志是文本记录，不是终端画面录像。
- 不单独记录键盘输入或命令参数；程序正常回显和主动输出的内容会写入日志。SSH/sudo 等关闭回显的密码输入不会被另行采集。
- 创建日志失败时不启动任务，并显示错误；运行中写入失败会在输出区显示警告。正常退出 App 会等待已完成任务的日志写入结束。
- 本机只登记日志目录位置，实际内容保存在脚本目录。移除 Workspace 或脚本配置不会删除已有记录；目录暂不可用时不会显示其中的记录，恢复后可刷新查看。复制或迁移库后，当前已配置脚本的日志目录也会被发现。

旧版本执行过但未保存的输出无法补录。日志不自动清理。执行历史窗口支持删除所选记录、清空当前筛选结果，以及清空全部已加载历史。筛选清空同时使用 Workspace、脚本和搜索条件；全部清空不受筛选影响。每次操作均需确认，会永久删除对应的 `.log` 和 `.json` 文件，保留脚本与配置，跳过正在运行或尚未完成日志写入的记录。暂不可用目录和无法解析的记录不能通过此界面清理；文件删除失败时显示提示，可刷新后重试。

## 1.5 多 Workspace 与设置

Workspace 是一个独立的脚本库目录，沿用现有 library.json 和 scripts/ 格式，不需要修改脚本库配置。

- 从侧栏顶部的 Workspace 菜单切换、添加或管理目录。侧栏隐藏时，切换器显示在工具栏。添加同一个目录会定位到已有登记，不会重复添加。
- 通过“设置…”（⌘,）打开管理窗口。“Workspaces”页可以添加、重命名、上下排序、打开、重新定位和移除登记；重命名只修改 App 中的显示名称。
- “终端”页可设置 10–24 pt 字体和滚动历史行数。字体立即生效，历史行数从下次运行生效，当前终端内容保持不变。
- Workspace 列表、顺序、上次选择和全局偏好保存在本机应用偏好中，不写进任何 library.json；旧版记住的目录会自动迁移为第一个 Workspace。
- 各 Workspace 在本次应用会话内分别保留所选脚本和参数值。即使脚本 ID、参数 ID 相同，也不会串值；关闭应用后运行参数不保留。
- 任务运行时可以切换 Workspace，底部终端持续属于所选执行。点击输出区中的脚本名称可返回对应库和脚本；全 App 支持多个执行会话。
- 移除仅删除本机登记，保留目录和文件。任务运行期间，所属 Workspace 不能移除或重新定位；任务结束后即可操作。
- 目录丢失或外置磁盘未连接时显示“目录不可用”。在设置中重新定位到包含 library.json 的目录，会保留 Workspace ID 和显示名称；不会移动或复制文件。

## 1.4 应用内交互终端

所有脚本统一在 App 内运行，无需选择执行方式。底部内嵌 SwiftTerm 原生终端，通过 PTY 支持 SSH 密码、首次连接确认、sudo、read、颜色与进度刷新。点击终端即可输入，输入密码时通常不会显示字符。键盘输入由终端传给脚本，App 不另行记录输入。

运行时输出区自动展开；收起输出区或切换脚本不会中断会话。结束后保留终端内容，再次运行创建新会话，多个会话可以并发执行。

- “中断”或终端内 Ctrl+C：向终端发送中断字符，由终端设置决定如何处理，通常中断前台程序。
- “停止”：向会话根进程组和属于同一会话的当前前台进程组发送 SIGTERM；仍未退出时可“强制停止”发送 SIGKILL。自行脱离会话的后台进程需自行管理。
- “复制日志”“保存日志…”：导出终端当前活动缓冲区的可读文本，包含配置行数以内的滚动历史（默认 10,000 行），不包含原始 ANSI 控制序列。全屏程序和覆盖刷新的内容反映终端缓冲区状态，不是逐字节录像。
- 密码是否回显由所运行程序控制；SSH/sudo 等通常关闭回显。请勿把密码写入参数默认值或让脚本输出密码。
- 旧配置的 `execution` 字段继续接受 `embedded`、`terminal`，但不再影响执行；App 保存配置时会省略该字段。

菜单快捷键：添加 Workspace ⌘O、导入 ⌘I、侧栏显隐 ⌃⌘S、输出显隐 ⌘J、停止所选任务 ⌘.；运行使用 ⌘Enter。

## 开始使用

1. 解压发布 ZIP，双击“ScriptDeck.app”；也可将应用拖到“应用程序”目录。
2. 点击“添加 Workspace…”（或按 ⌘O），选择包内“示例脚本库”目录。
3. 选择“示例 → 参数 → 下拉参数演示”，选择环境和模式后点击“运行”，即可查看参数传值。
4. Netfly 上传位于“部署 → Netfly”，直接在 App 底部终端执行，支持 SSH 密码输入。只有点击运行才会上传。

也可以选择自己的目录：已有 `library.json` 时直接加载；没有时会询问是否初始化空库。

## 脚本库目录

```text
我的脚本库/
├── library.json
├── library.schema.json
├── AI使用说明.md
└── scripts/
    ├── upload-netfly-app.sh
    └── show-options.sh
```

App 记住已登记的 Workspace 和上次选择项；目录迁移后，在设置中“重新定位”即可。目录登记保存在本机应用偏好中，不写入脚本库。运行参数只保存在内存；执行日志会按上述规则保存到脚本目录，默认值属于配置内容，请勿保存密码。

外部编辑 `library.json` 后，App 约每 0.8 秒检测并刷新；不会自动执行脚本。文件缺失、JSON 错误、重复 ID 或选项配置有误时，显示错误并保留当前会话上一份有效列表。保存前会检查外部变化，编辑期间发生刷新时需取消并重新打开编辑，以免覆盖更新。正在运行的任务继续使用启动时的配置。

运行中可以切换 Workspace 和脚本，底部任务名称始终标识当前终端所属的 Workspace 与脚本；不会因为切换而重启任务或改变工作目录。

## 配置格式

```json
{
  "$schema": "library.schema.json",
  "version": 1,
  "scripts": [
    {
      "id": "deploy-demo",
      "name": "部署演示",
      "group": "部署/示例",
      "description": "将所选环境作为第一个位置参数传入。",
      "file": "scripts/deploy.sh",
      "interpreter": "/bin/bash",
      "cwd": ".",
      "parameters": [
        {
          "id": "environment",
          "label": "目标环境",
          "type": "select",
          "required": true,
          "default": "staging",
          "options": [
            {"label": "预发布环境", "value": "staging"},
            {"label": "生产环境", "value": "production"}
          ]
        }
      ]
    }
  ]
}
```

- `id`：稳定且可读的标识。脚本 ID 在库内唯一；参数 ID 在该脚本内唯一。
- `name`、`file`：必填，分别为显示名称和脚本路径。`file`、`cwd` 相对于脚本库目录解析，也允许绝对路径。`cwd` 省略时使用脚本所在目录，填写 `.` 表示脚本库根目录。
- `group`：用 `/` 分隔多级分组；省略时为“未分组”。
- `interpreter`：默认 `/bin/bash`；也支持 `/bin/zsh`、`python3`、`node`、`direct` 或自定义解释器绝对路径。`direct` 要求脚本有执行权限和正确的 shebang。Python、Node 需自行安装。
- `execution`：旧版兼容字段，已弃用；新增配置无需填写，所有脚本都在应用内交互终端运行。
- `parameters`：按数组顺序逐个传入脚本；类型支持 `text`、`file`、`folder`、`select`。末尾空的可选参数省略，中间参数不能跳过。文件和文件夹参数中的相对路径也基于脚本库目录。
- `default`：可选默认值；`placeholder`：可选的输入提示。
- 下拉参数 `options` 支持 `[{"label":"显示名称","value":"实际传值"}]`，也支持 `["staging","production"]` 简写。选项传值需唯一且非空，默认值必须匹配选项传值。所有传值使用字符串。

App 内“编辑”分为“基本信息”和“参数配置”两页，可以增删参数和选项。配置会保存为上述规范字段；相对库目录内的绝对路径会转换为相对路径。配置文件应只使用 Schema 中的字段，额外自定义字段不会由 App 编辑器保留。分组树和脚本顺序由配置生成，参数顺序完全由数组确定。

## 导入和执行

- “导入”或将脚本拖到左侧列表，会把库外的脚本复制到本库 `scripts/` 中，保留原文件。重名文件自动追加编号。库内脚本不会重复复制。
- “新增”可以手动填写脚本路径；填写库外绝对路径时，配置会继续引用该外部文件。
- 删除仅移除配置，不删除脚本文件。
- 输出区位于窗口底部，默认收起，运行时自动展开。点击“运行输出”标题或按 ⌘J 可以展开、收起；展开后可拖动调整高度。终端支持选择、复制、粘贴、键盘交互和滚动历史；Python 默认使用无缓冲输出。
- 可打开示例库中的“示例 → 交互 → 交互终端演示”，手动体验普通输入、隐藏输入、确认和覆盖式进度刷新。该演示不会连接远程服务。
- 应用内执行会加载登录 Zsh 的环境，再切换到配置目录并启动解释器。参数逐个传递，不拼接为可执行 Shell 代码。应用运行用户主动选择的本地脚本，不提供额外沙箱隔离。

## 构建和打包

源码、构建工具、资源和文档已按职责分目录，详见 [项目结构与维护约定](Docs/Architecture.md)。根目录的 `build.sh`、`package.sh`、`test.sh` 作为统一入口，实际实现位于 `Scripts/`。

需要包含 Swift 6.3 或更高版本的 Xcode 或 Command Line Tools。使用 Swift Package Manager，SwiftTerm 固定为 1.99.2，完整依赖锁定在 Package.resolved。首次构建需要联网下载依赖，发布 App 运行时无需下载依赖。在项目根目录执行以下命令，只编译、签名并生成 ZIP，不运行脚本或测试：

```bash
bash package.sh
```

产物：`ScriptDeck/dist/ScriptDeck.app` 和 `ScriptDeck/dist/ScriptDeck-1.8.6.zip`。ZIP 内包含应用、示例脚本库和使用说明。

### 侧栏文件夹

点击左侧底部的文件夹加号创建文件夹；右键文件夹可创建子文件夹、在其中新增脚本或删除文件夹。空文件夹保存在 `library.json` 的可选 `folders` 数组中，旧配置无需迁移。删除文件夹会一并移除子文件夹，并将其中的脚本移到“未分组”；脚本配置、本地文件和执行历史均会保留。“未分组”是保留分组，不能删除。
